# 数据管理功能设计（导入 / 导出 / 撤销 / 清空）

> **这份文档只讲一块**：「设置 → 数据管理」这个二级页及其下钻的导入三级页。
> 记录的是这套功能的**设计决策与边界条件** —— 每个"为什么这么做"。
>
> 写法上刻意少贴代码 —— 代码会过期，设计意图不会。凡是给出代码片段的地方，
> 都是"这几行的措辞本身就是决策"的地方。
>
> 详细程度的标准：读完这一份，不需要再翻代码就能完整理解这套功能是怎么设计的。

---

## 1. 功能全景

```
设置 tab
 └─ 数据管理（二级页）
     ├─ 导入账单 ▾  ← 点击原地展开来源列表，不跳页
     │   ├─ 二级分类结构账单（其他记账软件）──► 三级页 · 外部账单流程
     │   └─ Flowt 备份 ────────────────────► 三级页 · 自家备份流程
     ├─ 导出备份 ──► 设置面板（BottomSheet）→ 系统保存对话框
     ├─ 撤销上次导入 ──► 确认对话框（3 秒倒计时）
     └─ 清空数据 ──► 确认对话框（5 秒倒计时 + 分类可选）
```

四个功能的共同点：**都是批量、不可逆、动用户全部数据的操作**。所以整块设计的重心
不在"怎么实现"，而在"怎么让用户不误操作、且事后能反悔"。

| 功能 | 一句话 | 可反悔吗 |
|---|---|---|
| 导入账单 | 把外部账单文件变成流水 | 可以 —— 撤销上次导入 |
| 导出备份 | 把流水写成 CSV / XLSX | 无副作用 |
| 撤销上次导入 | 删掉最近一次导入的全部流水 | 重新导入文件即可 |
| 清空数据 | 删掉全部流水（可选连分类） | **不能** |

## 2. 数据存储：三个位置，各有理由

最容易搞错的是"什么东西该存在哪"。这里有三处：

| 存什么 | 存哪 | 为什么 |
|---|---|---|
| 流水、分类 | 关系库（本项目是 Room/SQLite） | 业务数据，需要事务、外键、查询 |
| 界面偏好、**导入记录** | 键值存储（本项目是 DataStore） | 加一个字段不该触发数据库迁移 |
| 导入批次号 | 写在每条流水的 `source` 列上 | 见 §6.2 |

**导入记录**（本项目的 `ImportedFileRecord`）是这块功能的核心小数据结构，五个字段：

| 字段 | 用途 |
|---|---|
| `hash` | 文件内容的 SHA-256。用于「这个文件导过了」的提醒 |
| `fileName` | 展示用（「撤销上次导入」要告诉用户删的是哪个文件） |
| `importedAt` | 排序依据，**按它倒序，第一条就是"上次导入"** |
| `count` | 展示用 |
| `batchSource` | 那一次导入写进流水的批次号，撤销时按它删 |

> ⚠️ **存储格式要留兼容位**。本项目用字符串集合存（`hash|时间|条数|批次号|文件名`），
> 文件名放**最后一段**并配合 split 的 limit —— 否则文件名里含分隔符就会被切断。
> 解码时兼容旧格式（少于 5 段 = 没有批次号 = 那条记录不能撤销，但仍可用于重复提醒）。

## 3. 架构：三个可独立扩展的层

分层依据是一句话：**「格式差异」和「字段差异」是两件无关的事**。
CSV 与 XLSX 的差异只到「字节 → 二维表格」为止；再往后与"账单来自哪款软件、有哪些列"无关。

```
        (格式层，可加)     (两方向共用同一张)   (字段层，可加)      (落库 / 撤销)
导入： 字节 ──TableReader──► 二维表格 ──BillTable──► ImportedRow ──ImportService──► 数据库
导出： 数据库 ──ExportService──► 二维表格 ──CsvWriter / XlsxWriter──► 字节
```

**扩展点**（这张表是索引，具体步骤见 §8 扩展指南）：

| 将来要加的 | 需要动的地方 |
|---|---|
| 新文件格式（.xls / JSON / 剪贴板文本） | 新增一个 `TableReader` 实现并注册，**其余层不动**（§8.1） |
| 列的叫法不同（新软件的列名） | 往同义词表加词，逻辑代码一行不改（§8.2） |
| 新字段（账户、标签、币种） | 字段枚举加一项同义词 + 行模型加字段 + **数据库迁移**（§8.4） |
| 新导入来源（某软件的标准格式） | 来源列表加一行 + 一个 `ImportMode`，流程与落库不动（§8.3） |
| 收入记账 | 行模型已保留 `type` 信息，**导入层已经就绪**；但主要工作在导入之外（记账页、指标、报表都要跟着放开），不在本文档范围内 |

## 4. 导入

### 4.1 流程与状态机

三级页内部是一个四阶段状态机，**返回键按阶段回退**：

```
选文件 ──► 解析中 ──► 预览 ──► 结果
                       │
              （可改列绑定 / 分类去向，改动即时重算）
```

- **解析中 / 导入中不接受返回**：半途中断只会留下说不清的状态
- 预览阶段按返回 → 弹「放弃本次导入？」确认（解析结果与去向选择都会丢）
- 结果页按返回 → 直接关闭

### 4.2 取文件

用系统文件选择器（Android 是 SAF `OpenDocument`，无需存储权限）。

**MIME 类型不可靠**：有的文件管理器把 `.csv` 报成 `application/octet-stream`。
所以 MIME 收得宽（`text/*` + xlsx + octet-stream），**选定后再按文件名后缀校验一次**，
后缀不认识就明确报错。

### 4.3 格式层：字节 → 二维表格

**CSV** —— 两件"猜"的事必须做掉，因为导出的账单五花八门：

- **编码**：先看 BOM（UTF-8 / UTF-16LE / UTF-16BE）；没有 BOM 就**严格**试 UTF-8，
  失败回退 GBK。严格的意思是解码遇非法字节就抛异常、而不是替换成 `?` ——
  GBK 中文按 UTF-8 解几乎必然非法，这正是判据。
- **分隔符**：逗号 / 制表符 / 分号里取前几行出现次数最多的那个（从 Excel 复制粘贴出来的是制表符）。
- 引号转义按标准：`""` 表示字面引号，引号内的分隔符与换行属于字段内容。
- 换行先统一成 `\n` 再进状态机，省掉一半分支。

**XLSX** —— xlsx 本质是 zip 里装着几个 XML，读一份账单只需要两样：
`xl/sharedStrings.xml`（字符串表）与第一个工作表的 XML。

> **为什么手写而不引库**（是的，这一条值得单独说明，因为直觉上该用现成的）：
> Apache POI 在 Android 上不能直接用（缺 `java.awt`、缺完整 StAX，且 `poi-ooxml-schemas`
> 单包约 6.8 万方法引用，直接撞 65K 上限）；各种 Android 移植版都停在多年前、还要 multidex
> 与 2MB+ 体积；轻量的 `fastexcel-reader` 依赖 `javax.xml.stream`，而 Android 运行时没有这个包。
> 结论：读取场景下，标准库 ~200 行比背一个依赖划算，也不会被停维护的库卡住。

实现要点：
- 单元格的列位置取自 `r` 属性（`"C5"` → 第 3 列）。**不能按出现顺序追加** ——
  xlsx 会省略空单元格，按顺序追加会把列错位。
- 单元格类型：共享字符串索引 / 内联字符串 / 公式结果字符串 / 布尔 / 数字（默认）。
- 用 SAX 流式解析（Android 的 `SAXParserFactory` 与 JVM 都支持）；**不要用 Android 专有的
  `android.util.Xml`**，那样解析器就没法在 JVM 单测里跑。
- 日期在 xlsx 里可能是**数字序列号**，换算见 §4.5。

### 4.4 字段层：二维表格 → 流水行

**表头不在第一行也要能认**：扫描前 20 行，找"同时能认出时间列与金额列"的那一行。
导出的账单常带前置说明行（导出时间、账号之类），写死第一行会把说明行当表头。

**未识别的列不丢**：没被任何字段占用的列，原样存进行模型的 `extras`（列名 → 原值）。
本地现在没有"账户""标签"这些字段，但数据先留着，将来实体加字段时直接接上。

### 4.5 三个解析函数（最容易出细节错的地方）

**金额 → 整数分**：
- 用 `BigDecimal(...).movePointRight(2).setScale(0, HALF_UP).longValueExact()`，**绝不用 Double**。
- 容忍各家的写法：`¥150.98`、`1,234.56`、`150.98元`、`-21.08`、`(150.98)`（括号是财务软件的负数写法）。
- 解析不出来返回 `null`，由调用方计入"无法解析的行"。

**时间 → epoch 毫秒**：
- 支持多种格式（`yyyy-MM-dd HH:mm:ss`、`yyyy-MM-dd`、`yyyy/M/d`、`yyyy年M月d日`……），
  从长到短试。
- ⚠️ **必须校验整串都被消费掉**。多数日期解析器是**前缀匹配**：用 `yyyyMMdd` 去解
  `20260904134009` 会安静地得出 2026-09-04 并丢掉后六位。要自己检查解析位置等于字符串长度。
- **精度归一**：缺的位补 0，只有日期则取当天 00:00（本地时区）。归一后是确定值，
  后续一切（判重、显示）都基于它。
- 纯数字且落在合理范围（0 < n < 80000，约 2119 年前）时按 **xlsx 序列号**换算：
  基准是 1899-12-30（偏移 25569），且算出来的是"本地墙上时间"，要减掉时区偏移。

**列名归一化**：去空格、全角转半角、**丢掉括号里的内容**（通常是单位）、统一小写。
于是「金额(元)」「金额（元）」「 金额 」都归到「金额」，同义词表里只写一种写法。

### 4.6 列绑定

按**列名**绑定，不按列位置（各家列顺序都不同）。三条规则：

1. **同义词表自动匹配** —— 每个字段配一组叫法。**这张表就是"软件差异"的唯一落点**，
   换一款软件多数情况下只是补几个词，逻辑一行不用改。
2. **未识别的列进 `extras`**（见 §4.4）。
3. **匹配不上降级为手动** —— 时间或金额没匹配上时**不报错退出**，而是在预览页列出实际
   表头让用户用下拉框指定。遇到没见过的软件，用户自己就能导，不需要等发版。

#### 分类列要单独处理

分类列可能**有多列、层数不定**（树有几层就有几列），所以它不在字段枚举里：

- 先按显式同义词认前两级（`记账分类`/`分类`/`一级分类` → 1 级；`分类子类`/`子分类`/`二级分类` → 2 级）
- 再按 `N级分类` / `分类N` / `N级类别` 的模式认更深的层级，**中文数字也要转**
  （一→1、十二→12、二十三→23）
- 识别出的列按层级排序，拼成路径

这样自己导出的任意深度文件都读得回来 —— 闭环在任意层级下都成立。

#### 绑定之后必须做类型校验

只按列名配对不够：用户手滑把「金额」指到日期列，整批数据就成了垃圾。做法：

- 拿绑定去试解析**前 20 行有数据的行**，按字段类型判定：金额列要能解析出钱、时间列要能
  解析出日期；分类、备注、收支类型是自由文本，不校验
- 三级反馈标在对应行上：全通过 ✓ / 部分失败「3/20 行无法解析」/ 全失败
- **金额或时间列整列都解析失败时禁用「确认导入」** —— 那种情况导进去只会是 0 笔或一堆垃圾
- 校验随每次改动即时重算，并驱动"最近 N 条预览"一起变，绑错了立刻看得见

### 4.7 分类去向

账单里的分类路径 → 本地分类，三种去向：

| 去向 | 含义 | 落库时 |
|---|---|---|
| `Existing(categoryId)` | 绑到某个已有分类 | 直接用它 |
| `Create` | 本地没有同名分类，按路径**逐级创建** | 逐级建出来 |
| `Skip` | 这个分类下的流水不导入 | 计入跳过数 |

默认策略：**同名匹配，缺则新建**。每一条都能由用户在预览页改成任意一种。

**账单里没有分类的行走"未分类"**：如果某行没有分类列、或分类列全为空，归到一个固定的
「未分类」路径上（同样参与映射，用户也能把它改指到别处）。这样"一笔流水必须绑定一个分类"
这条约束不会被导入打破 —— 否则落库时会因为分类为空而失败。

逐级创建要复用**已有的分类创建逻辑**（路径生成、同级重名检查都在那里），
不要自己拼 SQL —— 两处规则早晚会跑偏。

**分类去向列表只列"至少有一条流水没被判重跳过"的分类**：某分类下的流水全是重复的，
它选"新建"还是"跳过"结果都一样，摆出来只是让列表变长。

> ⚠️ 但这个过滤的**基准是"没被判重"，不是"会导入"** —— 后者会把用户主动设为「跳过」的
> 分类也滤掉，那用户一旦跳过就再也改不回来了。

### 4.8 判重：两层，缺一不可

**第一层 · 文件级**：对文件字节算 SHA-256。导入成功后记进导入记录；再次选中同一文件时，
预览页给出警告并**二次确认**。

> 这一层为什么必需：行级指纹里含分类 id，用户第二次把某个分类改成「新建」或指到别的分类，
> 指纹就不同了；列绑定改错同样会改变时间戳。**只靠行级判重，会把同一批数据放进库两遍。**
> 文件哈希与分类映射、列绑定都无关，正好挡住这种情况。

**第二层 · 行级**：指纹 = **时间（毫秒精确）+ 金额（分）+ 分类 id + 备注**，四者全等才算重复。

几条刻意的取舍：

- **不做时间容差**。同一份数据从同一款软件导出，时间戳逐毫秒一致；而 ±60 秒容差会把
  同一分钟内两笔相同的消费误判成重复。宁可漏判（用户在列表里看得见、能手动删），
  不可误判（静默吞掉真实流水）。
- **保留分类 id**：它能挡住「同一天、同金额、无备注」的两笔真实消费被误判成重复 ——
  账单只精确到天时这种碰撞并不罕见。跨导入的分类选择差异由第一层兜住。
- **备注空值统一成 `null`**，避免 `""` 与 `null` 被当成两个不同的值。
- **文件内的重复保留**，只与「导入前已有数据」比对。文件里两行一模一样，更可能是用户真的
  消费了两次，丢掉是数据损失；而多记一笔用户看得见。摘要卡会写明「文件内有 N 组完全相同的
  记录」让用户知情。
- **重复数在预览阶段就算出来**（拿导入前的指纹快照做内存比对），不是等导完了才说跳过了几笔。

### 4.9 预览区

只列**真正会导入**的行（排除重复的、以及分类去向为「跳过」的），**按时间倒序**取最近 10 条。

每行显示四项：**时间（带年份和秒）、分类（去向落定后的结果）、备注、金额**。

三条设计意图：

1. **为什么要预览**：绑定的列对不对、金额有没有串行，用户看这几行的日期与金额一眼就知道。
   这是导入前最后一道人工校验。
2. **为什么显示"去向落定后"的分类**：用户把某个账单分类改指到别的分类后，显示原始路径会
   与实际结果对不上 —— 看到什么，导进去就该是什么。
3. **标题文案**：不足 10 条时只写「预览」（全在这里了），超过 10 条才写「最近 10 条预览」。

### 4.10 落库

**单个事务**内完成「建缺失分类 + 插入流水」，中途失败全部回滚，不留半截数据。

每条流水写上**批次号**（`source` 字段），形如 `import:bill:1758585600000`。
这是撤销的唯一依据（见 §6.2）。

**三个派生值的口径必须统一** —— 摘要里的"可导入 N 笔"、确认按钮文案、预览行，
全部从一个函数出发（"真正会导入的行下标"）。

> ⚠️ 分头算早晚会在边界上对不上。本项目就踩过两次：
> ① 用「总数 − 重复数 − 跳过分类的行数」相减，当某个分类既被跳过、其流水又重复时，
> 同一笔会被扣两次；
> ② 落库时用它自己的口径（见 §9 的坑 1）。
>
> **分类去向列表是刻意的例外**：它用"没被判重"作基准，而不是"会导入" ——
> 理由见 §4.7（否则用户一旦把某个分类设为跳过，它就再也改不回来了）。

### 4.11 自家备份模式

同一个导入流程要服务两种意图完全不同的场景，靠 `ImportMode` 区分：

| 模式 | 入口 | 行为差异 |
|---|---|---|
| 外部账单 | 「二级分类结构账单」 | 完整预览：列绑定 + 分类去向都要过目 |
| 自家备份 | 「Flowt 备份」 | 列绑定与分类去向**默认折叠**成一行摘要，主按钮文案是「恢复 N 笔流水」 |

自家备份零操作的依据：列名是我们自己写出去的、分类路径就是本地这棵树，没什么可确认的。
但两个区仍可展开修改。

**模式由入口决定，不靠猜文件内容。** 但仍要做一次格式校验：从备份入口进来却没认出自家
表头时，明确提示「请从二级分类结构账单导入」，而不是让它静默走完流程。

#### 导出与识别必须共用同一组列名常量

「导出时写出去的列名」和「识别自家备份时的判据」必须是**同一份定义**。
各写一份字符串，将来改一边忘了另一边，编译不会报错，只会在用户那里表现为
「这不像 Flowt 导出的备份文件」。

## 5. 导出

### 5.1 三个选项

| 选项 | 取值 | 备注 |
|---|---|---|
| 格式 | CSV / XLSX | |
| 时间范围 | 全部 / 自定义 | 自定义**精度到天**：起始日取 00:00，结束日取 23:59:59.999（含当天） |
| 分类列形式 | 展开为多列 / 单列完整路径 | 见下 |

每项后面带上该范围的条数，用户选之前就知道会导出多少。

**分类列形式**（本地分类是树，导出成表格有两种表达，各有真实用途）：

- **展开为多列**（默认）：**树有几层就展开几列**（「一级分类」「二级分类」…不设上限），
  某行层级不足则留空。这是绝大多数记账软件的账单结构，在 Excel 里能直接按一级分类筛选、做透视表。
- **单列完整路径**：一列装 `餐饮/外卖/午餐`，紧凑无损，适合自己看或纯备份。

### 5.2 CSV 必须带 BOM

不带 UTF-8 BOM 的话，中文 Windows 上 Excel 双击打开就是乱码。这不是优化项，是分水岭。

日期按 `yyyy-MM-dd HH:mm:ss` 字符串写、金额不带货币符号，这样别的工具也能直接吃进去。

### 5.3 XLSX 的最小实现

只生成必需的 5 个部件：`[Content_Types].xml`、`_rels/.rels`、`xl/workbook.xml`、
`xl/_rels/workbook.xml.rels`、`xl/worksheets/sheet1.xml`。

两个刻意的简化，都是为了"能读回来"：

- 文本一律用 `inlineStr` 单元格，**不生成 sharedStrings.xml** —— 省掉字符串表整块复杂度，
  Excel 完全支持这种写法
- **日期按字符串写**而不是日期序列号 + 格式：ISO 字符串在 Excel 里排序结果与时间排序一致，
  而且这样写出去的内容能被自己的解析器读回来，闭环才成立

还需要：XML 转义（`& < > " '`，并**丢掉 XML 1.0 不允许的控制字符**，否则整个文件打不开）、
列号转字母（1→A、27→AA）。

### 5.4 闭环：导出的文件能直接再导入回来

**列名与导入侧的同义词表对齐**，于是导出的文件都能直接再导入：换手机、重装应用后用它恢复，
同时也天然证明备份是完整的。

### 5.5 导出不做内容预览

导出没有需要逐条拍板的分支（导入之所以要预览，是因为列绑定可能错、分类去向要人工定）。
选完三个选项和保存位置就已经表达了全部意图，再确认一次是多余的一步。

### 5.6 一个已知的边界：Excel 中转会丢秒

导出的 CSV 用 Excel 打开再另存回 CSV，Excel 会按自己的显示格式重写日期：
`2026-09-04 13:40:09` → `2026/9/4 13:40`。解析器认得出这个格式（导入成功），
但时间戳少了 9 秒，与库里的原记录指纹不同 —— **再导一次会重复记账，而且文件内容变了、
哈希拦不住**。XLSX 没这个问题（日期是字符串，Excel 不会转）。

这不是承诺范围（"导出的文件原样导回来"是成立的），但值得在文档里留一笔。

## 6. 撤销上次导入

### 6.1 入口为什么在数据管理页，而不是导入结果页

第一版把撤销按钮放在导入结果页，结果是：**用户还没看到实际效果**（还没回主页看流水对不对），
等他看完想撤的时候，那个页面早关了，找不到入口。

所以撤销**从导入流程里剥离出来**，作为数据管理页的一个常驻入口。导入结果页只留一句
引导：「想撤销这次导入，可到「设置 → 数据管理 → 撤销上次导入」」。

### 6.2 判定依据：批次号，不是流水 id 列表

每条流水在导入时写入一个批次号（`source` 字段），撤销时按它整批删除。

> **为什么不用 id 列表**：直觉上"记录这次导入的流水 id"更直接，但代价是：
> 几千个 id 要么拼成一个很长的字符串塞进键值存储，要么给数据库加张表（要迁移）。
> 而**批次号本来就贴在每条流水上**，且**编辑流水时它是保留的**（编辑只改被改的字段），
> 所以用户改过金额、分类、备注之后照样撤得掉 —— 一个字符串搞定。

**前提**：编辑流水时必须保留 `source` 字段。这是整套撤销方案唯一的依赖 ——
改动编辑逻辑时要留意，一旦 `source` 在编辑时被清掉，撤销会静默失效（删 0 条，不报错）。

### 6.3 "上次"的取法

导入记录**按时间倒序，第一条就是上次导入**。撤销时会抹掉这条记录，于是"上次"自然变成
再上一次 —— **免费获得连续撤销**（导入 A、B、C 后可以连撤三次）。

### 6.4 边界与交互

- **自动创建的分类保留**：用户此后可能已经改过它们、甚至往里记了账，连带删除是二次损失
- **没有可撤销的导入时，入口置灰不可交互**（而不是隐藏）—— 让用户知道有这个功能
- 旧版本留下的记录没有批次号，认不出那批流水，一律按"无可撤销"处理
- 确认对话框显示"将删除「文件名」在 X 月 X 日导入的 N 笔流水"
- **3 秒倒计时**后才能点确认（比清空的 5 秒短：影响面小，但仍是不可回退的批量删除）

## 7. 清空数据

### 7.1 删除顺序不能反

先删流水、再删分类。分类的外键是 `NO_ACTION`（本项目刻意如此，见 §9 的坑 5），
流水还在时删分类会被数据库直接拒绝。

这是整个应用里**唯一**会绕过"删除分类前必须迁移流水"这条规则的操作 —— 它走的是相反的次序。

### 7.2 分类是可选项

用勾选框让用户决定，**默认不勾**。理由：流水是主体，分类树是用户一条条建起来的，
顺带删掉一个他未必想删的东西，比少删更糟。

### 7.3 连带清掉导入记录

否则会出现：清空数据后重新导入同一个文件，却看到「这个文件导入过」的提醒。

这一步走键值存储、**不在数据库事务里**（两者本来就不同存储），所以：

- 顺序是先清数据库、再清记录
- 第二步用 `runCatching` 包住，失败也不让整个操作报错 ——
  否则用户会看到"点了没反应"，而账目其实已经清空了
- UI 上不必说明清了它（用户不关心）

### 7.4 清空的范围要划清楚

清掉的只有**流水**和（可选的）**分类**。**界面偏好不动** —— 配色方案、首页指标选择、
临时颜色微调这些跟"账目数据"是两回事，用户点"清空数据"时想的不是"重置我的外观设置"。

如果这些偏好和导入记录存在同一个键值存储里（本项目就是），实现时要**逐个键操作**，
不要图省事整个清空。

### 7.5 交互

- 入口是警示色（标题用 error 色）
- 确认对话框显示"将删除全部 N 笔流水，此操作无法撤销"，并提示"清空前建议先导出一份备份"
- **5 秒倒计时**后才能点确认 —— 这个按钮删的是全部账目，必须"看着它数完"才能按下去
- 倒计时期间按钮文字用次要色，**能按下去时才变红**（否则灰着的红字看着像"现在就能点"）

## 8. 扩展指南

四类扩展，各自只动有限的几层 —— 这是 §3 分层方式换来的。按"从最简单到最完整"排列。

### 8.1 加文件格式（.xls / JSON / 剪贴板文本……）

只动**格式层**。

1. 实现 `TableReader` 接口：`canRead(fileName)` + `read(bytes): List<List<String>>`
2. 在注册表里注册一项
3. 后缀加进"支持的后缀"集合（UI 用它给用户提示，并在选完文件后校验）

**不用动的**：字段层、判重、撤销、导出 —— 它们只认"二维表格"，不关心字节从哪来。

三个注意点：

- `read` 抛出的格式异常，消息会**直接展示给用户**，写成人话（参考现成的那几条：
  "不是有效的 xlsx，或文件已损坏"）
- 用平台通用的 XML / JSON API，别用某个平台专有的（比如 Android 的 `android.util.Xml`），
  否则这个读取器就只能在真机上验证
- 非文件的来源（剪贴板文本、分享意图传入的内容）也能落在这一层：
  `canRead` 按约定的伪文件名（如 `clipboard.txt`）判断即可

### 8.2 加字段同义词

只动**字段层的同义词表**，一行逻辑代码都不用改。

适用场景：新软件的列名叫法不同（写「发生额」而不是「金额」）。往对应字段的 synonyms
里加词即可。

两个注意点：

- 匹配是**归一化之后**比的（去空格、全角转半角、丢掉括号内容），所以表里写「金额」
  就能匹配「金额(元)」「金额（元）」，不必把变体逐个列上
- **一列只归一个字段，先到先得**。加词时留意别和已有词撞车 —— 撞了不会报错，
  只是后声明的那个匹配不到

### 8.3 加新的导入来源

最完整的一种，会牵动最多地方。以"接入某款软件的标准格式"为例。

#### 第一步：先判断它落在哪一层

| 情况 | 要做的 |
|---|---|
| 只是文件格式不同 | 见 8.1 |
| 只是列名不同 | 见 8.2，一个字都不用写 |
| **列名与分类映射都固定**（该软件总是导出那几列、分类总是那几棵树） | 加一个 `ImportMode`，见下 |

多数情况只需要前两步。只有当"这个来源的文件名/列名/分类结构都是已知的"时，
才值得为它加一个模式。

#### 第二步：加 `ImportMode`

在模式枚举里加一项，然后在来源列表加一行入口（列表是原地展开的，加一行不影响别处）。

这个模式要回答一个问题：**要让用户做多少确认？**

- 列名固定、分类就是本地这棵树（类似"自家备份"）→ 列绑定与分类去向**两个区都折叠**
- 列名固定、但分类去向需要用户拍板 → 只折叠列绑定
- 只是少几个同义词 → 其实不需要新模式，用 8.2 就够了

模式由**入口**决定，不靠猜文件内容。但入口仍要做格式校验：从该入口进来却没认出
预期表头时，明确提示换入口，而不是静默走完流程。

#### 第三步：确认三处不受影响

这三个**默认不用改**，但加来源时要逐个确认一遍：

1. **判重**（§4.8）—— 文件级哈希照常工作（与来源无关）；行级指纹用的是解析后的值，
   也与来源无关。**唯一的例外**：如果该软件导出的时间精度只到天，会让"同一天、同金额、
   无备注"的两笔碰撞，需要评估这笔账值不值得为它做特例
2. **撤销**（§6）—— 批次号机制与来源无关，自动适用，不用动
3. **导出**（§5）—— 不受影响。除非该软件要求一个特定的格式才能导回去，那才需要动导出侧

#### 第四步（可选）：预设绑定

来源固定时，可以在解析后直接给出一套预设的列绑定，跳过自动匹配 ——
这样从这个入口进来的用户是零操作。

注意预设绑定要**可被用户覆盖**（预览页的列绑定区仍可展开改），
否则遇到该软件的新版本改了列名，用户就无路可走了。

### 8.4 加字段（账户、标签、币种……）

比 8.2 多几步，因为要把数据真正落到库里：

1. **字段层**：字段枚举加一项 + 同义词（同 8.2）
2. **行模型**：加一个字段，解析时填进去
3. **落库**：写进实体的新列 —— 这一步要**数据库迁移**（本项目刻意禁用了破坏性迁移，
   必须手写迁移脚本）
4. **界面**：要在哪儿展示这个新字段

好消息是**旧文件不用重导**：未被识别的列一直原样存在行模型的 `extras` 里（§4.4），
新字段上线后，那些数据还在解析结果里等着被用上。

> ⚠️ 迁移是这个场景里唯一有真实风险的一步。失败要能回滚，且**绝不能**为了省事启用
> 破坏性迁移 —— 那会静默清空用户账目。

## 9. 踩过的坑（必读）

这几条都是真实发生过的，不是假想。

### 坑 1：预览和执行用了两套口径

预览判重时读的是**映射表**（账单分类路径 → 目标分类 id），而落库时拿**账单里的原始路径**
去查本地分类表。当用户把「本地没有的分类」改指到某个已有分类时：

- 预览：映射表里查得到 → 算作可导入
- 落库：原始路径在本地不存在 → 全部计入"按去向跳过"

结果就是**预览说"可导入 7 笔"，点下去变成"新增 0 笔、按去向跳过 7 笔"**。

**教训**：凡是"某行会怎么处理"的判断，预览与执行**必须查同一张表**。本项目现在是
四处（判重、可导入计数、预览、落库）统一到一套映射口径。

### 坑 2：用相减算"可导入多少笔"

`总数 − 重复数 − 跳过分类的行数`，当某个分类既被设为跳过、它底下又有重复流水时，
同一笔会被扣两次 —— 计数偏小。

**教训**：这类计数要**直接数**（遍历一次判定"这一行会不会导入"），不要用集合运算相减。

### 坑 3：分类去向的过滤基准搞错

用"会导入的行"去算该显示哪些分类，会把用户主动设为「跳过」的分类也滤掉 ——
一旦跳过就从列表消失，再也改不回来。

**教训**：过滤列表时要想清楚基准是什么。"没有意义的条目"（全是重复的）该滤，
"用户主动排除的条目"不该滤（否则无法撤销这个决定）。

### 坑 4：日期解析的前缀匹配

`yyyyMMdd` 去解析 `20260904134009` 会得出 2026-09-04 并丢掉后六位，不报错。

**教训**：自己校验"解析位置 == 字符串长度"。

### 坑 5：分类的删除保护与清空操作冲突

本项目的规则是"分类下还有流水就拒绝删除"（外键 `NO_ACTION`），这对日常操作是对的
（防止流水失去分类）。但"清空数据"需要绕过它 —— 靠**调换删除顺序**（先流水、后分类），
而不是放开外键约束。

**教训**：破坏性操作要在一个事务里按依赖顺序做，别为了它把数据层的保护拆掉。

### 坑 6：导出与识别各写一份列名

两处独立的字符串常量，值恰好一致所以能用。将来改一处、忘了另一处，编译不报错，
只在用户那里表现为"这不像自家备份文件"。

**教训**：**两处必须一致的字符串，就让它们是同一个常量。**

### 坑 7：导入记录忘了在清空时一并清理

清空数据后重新导入同一个文件，会看到「这个文件导入过」 —— 但数据明明已经清空了。

**教训**：凡是"状态清理"，要盘一遍**所有存了这个状态的地方**（本项目有数据库 + 键值存储两处）。

### 坑 8：撤销按钮放在"还没看效果"的页面上

第一版把撤销按钮放在导入结果页。功能没错，位置错了 —— 用户要的是"回主页看完效果，
不满意再撤"，而不是"刚导完就撤"；等他看完想撤时，那个页面早关了。

**教训**：不可逆操作的反悔入口，要放在用户**产生反悔念头时所在的地方**，
而不是操作发生的地方。
