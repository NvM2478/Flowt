# Flowt 外观（配色系统）设计

> **这份文档只讲一块**：「设置 → 外观」这个二级页及其全部延伸 —— 取色弹窗、低对比待决胶囊、配色方案的持久化。
> 记录的是这套功能的**设计决策与边界条件** —— 每个"为什么这么做"。
>
> 写法上刻意少贴代码 —— 代码会过期，设计意图不会。
>

---

## 0. 功能全景

```
设置 tab
 └─ 外观（二级页）
     ├─ 主题（明暗模式）──► 下拉：跟随系统 / 浅色 / 深色
     ├─ 配色方案
     │   ├─ 自动（跟随系统取色）◄── 壁纸三色自推导，回前台自动刷新
     │   ├─ 六套内置预设 ──► 单选切换（切换即清空临时微调，见 §5.1）
     │   └─ 我的方案 ──► 长按气泡菜单：重命名 / 删除
     └─ 自定义颜色（18 个角色）──► 取色弹窗（色板 + HSV 取色盘 + 重置 / 应用）
                                      │
              应用低对比配对色时 ──► 全局待决胶囊（保留 / 撤销，悬浮所有页面）
```

三类配色来源的对照 —— 它们共享同一套角色与解析管线，差异只在"颜色的来源"：

| 来源 | 颜色从哪来 | 受明暗模式影响 | 临时微调 | 可保存 / 删除 |
|---|---|---|---|---|
| 自动 | 壁纸三色自推导（§4.2） | 是（明暗也决定推导参数） | 支持 | —（跟随系统，无实体） |
| 内置预设 | 六套手工校准的字面量 | 是（每套含浅 / 深两份） | 支持 | —（内置，不可删） |
| 我的方案 | 保存时刻的全部角色生效值 | **否**（固定颜色的自包含方案） | 支持 | 可保存（同名覆盖）、可重命名、可删除 |

设计三原则（所有规则由此推导）：

- **面积与饱和度成反比**：大量重复出现的元素必须最安静，强调色只留给小面积关键元素；
- **底色让人改，文字代码算**：底色类角色用户随便调，配对文字由算法保证对比度 ≥ 4.5:1，手动覆盖是受保护的高级行为；
- **一份规则**：预设与动态取色、浅色与深色，全部颜色观感规则只实现一份，任何路径不得手工复制（§8 的坑 1 就是违反它的下场）。

## 1. 核心模型：部件 → 颜色位 → 角色 → 颜色

```
界面部件 ──读──> 颜色位（FlowtColors 总表，绑定关系代码写死）
                    │
                    ▼
                角色（RoleKey 枚举，18 个，用户可自定义其颜色值）
                    │
                    ▼
                生效颜色（覆盖值 > 派生值 > 基底值）
```

关键设计边界：

- **用户只能改"角色对应的颜色值"**，不能改"哪个部件用哪个角色"——部件与角色的绑定收敛在颜色位总表，由代码写死；
- 部件消费颜色有**两条通道**：自家部件（卡片、按钮、取色器等）读 `FlowtColors` 的颜色位字段；Material 3 内置组件（Scaffold、Switch 等）读 `ColorScheme` 色槽——两条通道由同一份角色值驱动，永不打架；
- 界面代码**禁止直接引用** `MaterialTheme.colorScheme.xxx`（唯一例外是 theme 包自身的实现）。

## 2. 角色注册表（18 个）

角色的三分类：

| 分类 | 含义 | 自定义行为 |
|---|---|---|
| `BASE` | 底色类 | 自由取色，无派生 |
| `ON` | 配对文字类 | 默认**实时派生**自配对底色（保证对比度）；手动改过即进入覆盖态（受保护，低对比时走待决胶囊流程） |
| `FREE` | 独立语义色 | 自由取色，无派生 |

完整注册表（角色 → 分类 / 派生基准 / 写入的色槽 / 消费部件）：

| 角色 | 分类 | 派生基准 | 写入色槽 | 主要消费部件 |
|---|---|---|---|---|
| 页面底色 | BASE | — | surface, background, surfaceDim | Scaffold：三个主 tab 与全部二级页的背景 |
| 卡片底色 | BASE | — | surfaceContainerLow | 流水按天卡片、取色弹窗底 |
| 中性底色 | BASE | — | surfaceVariant, surfaceContainerHigh | 输入框等 M3 组件内部 |
| 记账页底色 | BASE | — | primaryContainer, surfaceContainerHighest | 记账页整页、揭场动画圆、流水条目 |
| 导航栏底色 | BASE | — | surfaceContainer | 主页底部导航栏、二级页顶栏（部件显式传参） |
| 正文文字 | ON | 卡片底色 | onSurface, onBackground | 分类名、设置标题等主要文字 |
| 次要文字 | ON | 卡片底色 | onSurfaceVariant | 时间、备注、小计等辅助信息 |
| 描边与分割线 | ON | 卡片底色 | outline, outlineVariant | 输入框边框、色块描边 |
| 导航栏文字 | ON | 导航栏底色 | —（部件显式传参） | 底部导航与二级页顶栏的文字；未选中态自动 60% 透明 |
| 主色 | BASE | — | primary | 保存按钮、FAB、拖拽角标 |
| 主色上的文字 | ON | 主色 | onPrimary | 上述强调底上的文字 |
| 指标卡底色 | BASE | — | tertiaryContainer, surfaceTint | 首页指标卡、报表合计卡 |
| 指标卡文字 | ON | 指标卡底色 | onTertiaryContainer | 上述容器上的文字 |
| 记账页文字 | ON | 记账页底色 | —（部件显式传参） | 记账页与流水条目上的文字 |
| 导航栏选中块 | BASE | — | secondaryContainer | 底部导航当前项背后的指示块 |
| 危险色 | BASE | — | error | 删除、清空等危险操作 |
| 危险色上的文字 | ON | 危险色 | onError | 危险色底上的文字（如拖拽角标） |
| 支出金额 | FREE | — | tertiary（仅为槽一致化，真实消费走颜色位） | 流水与报表的支出数字 |

三个**不写色槽**的特例（导航栏文字、记账页文字，及支出金额的真实消费）：它们的消费部件显式读颜色位，不经过 M3 色槽——目的是避免与其他角色写同一槽互相覆盖（见 §9 的坑 5）。

> ⚠️ 唯一的**刻意共享**：「记账页底色」同时写 `primaryContainer` 与 `surfaceContainerHighest` 两个槽（语义上就该一致，M3 的底面板与最高容器同步）。除它之外每个槽只有一个归属角色——新增角色时若想写的槽已有归属，先想清楚是不是该复用那个角色（见 §9 坑 5 的教训）。

为什么是这 18 个：它们是"用户看着界面能指认、且愿意调"的全部颜色 —— 每个都对应界面上可见的一块，没有为 M3 内部派生槽（surfaceContainerHigh 之类）单开角色；反过来，M3 组件内部要用到的槽全部有角色覆盖（见 §3 第 5 步），不存在"改不到的角落"。

## 3. 颜色解析管线

每次主题层重组，按以下步骤计算（全部按内容记忆化，任何输入不变则不重算）：

1. **选定基底方案**：按 `selectedThemeId` + `brightnessMode`（自动取色再乘以壁纸版本号）得到一份 M3 `ColorScheme`；
2. **合成覆盖表**：`合并覆盖 = 我的方案存的值 + 临时微调`（后者优先）；
3. **算角色生效值**（18 个）：每个角色取值优先级为
   - 用户覆盖值（合并覆盖表中存在）→ 直接用；
   - ON 类且其配对底色被用户改过 → **派生**（见下）；
   - 否则取基底配色中该角色绑定的槽值；
4. **算角色默认值**：每个角色"清掉自身临时微调"后的颜色（保存方案下 = 方案存的值；内置方案下 = 基底槽值）——供取色弹窗的重置判断与回退使用；
5. **写色槽**：生效值写入 `ColorScheme` 喂给 M3 内置组件；
6. **装配颜色位表**：同一份生效值装配成颜色位对象，供自家部件读取。

**派生算法（`deriveOnColor`）**：输入底色，输出其上的文字色——

- 提取底色色相（HSV），饱和度收敛到 ≤ 0.7（文字不需要底色那么艳）；
- 第一段：明度向远离底色方向拉 0.55 起步，步进 0.04 继续拉，直到对比度 ≥ 4.5:1；
- 第二段（明度到边界仍不达标时——红/粉/蓝这类色相的"最亮纯色"亮度不够）：降饱和度（步进 0.1）向纯白/纯黑收敛，必然达标；
- 底色明暗的判定：明度 < 0.5 为暗底。

**对比度**：WCAG 相对亮度公式；阈值常量 `4.5:1`（正文可读底线），是所有警告流程的判定依据。

## 4. 配色方案体系

### 4.1 预设方案（六套）

每套 = 一份浅色 + 一份深色 `ColorScheme` 字面量，构造时统一经过**方案化处理**（浅深都走，与动态取色同一条规则）。处理清单与参数：

| 处理槽 | 浅色 | 深色 |
|---|---|---|
| 记账页底（primaryContainer） | 主色色相雾色（S0.04 / V0.965） | 主色色相雾深（S0.05 / V0.17） |
| 指标卡底（tertiaryContainer） | 主色相雾彩（S0.08 / V0.94） | S0.10 / V0.30 |
| 页面最高容器（surfaceContainerHighest） | 同记账页底 | 同记账页底 |
| 卡片底（surfaceContainerLow） | 主色相注入（S0.10 / V0.94） | 主色相注入（S0.10 / V0.13） |
| 导航栏底（surfaceContainer） | 主色相注入（S0.08 / V0.955） | S0.08 / V0.10 |
| 导航栏选中块（secondaryContainer） | 主色相注入（S0.20 / V0.90） | S0.18 / V0.25 |
| 页面底三槽（surface / background / surfaceDim） | 不动（保留字面量的冷暖微差） | 统一纯黑 #000000 |

这条规则是深浅模式"观感分层"的核心：页面底最安静 → 导航栏底 → 卡片底逐层加深加彩，强调色只出现在小面积元素上。**颜色来源全部是各方案自己的主色色相**——六个方案的同类容器会分别带上紫 / 青 / 橙 / 蓝 / 绿 / 玫的色调，逐行可辨。

### 4.2 自动方案（跟随系统取色）

**不使用** framework 的 `dynamicColorScheme` 直接结果——部分系统（HyperOS 实测）不向第三方 app 推送壁纸调色板，换壁纸后颜色纹丝不动。替代实现：

1. 读 `WallpaperManager` 的壁纸三色（主色 + 两个次要色）；
2. 三色各自**色相保真**、明度/饱和度归一到主题对应的强调色带（浅色 V0.45、深色 V0.80）；
3. 大面与容器走同一条方案化处理（与预设同规则）；
4. **壁纸版本号**：每次回到前台递增（换壁纸必然离开过 app），使壁纸取色的记忆化失效、重新查询。

### 4.3 我的方案（保存 / 重命名 / 删除）

- **保存**：存**全部角色的生效值**（自包含——删除它不影响任何东西，切回它不依赖当时的基底），另记录保存时刻处于派生态的配对文字角色（这些角色应用方案后继续自动匹配）；
- **默认名避让**：默认「我的配色」，被占用则依次尝试「我的配色 (N)」，取**最小可用序号**（删除中间的方案后序号可复用）；
- **重命名**：长按方案行 → 气泡菜单 → 重命名。新名与另一个方案撞名 = **覆盖**（原同名方案删除，名字转移）；正在使用的方案被重命名时，选中态 id 同步更名；
- **删除**：长按 → 气泡菜单 → 删除（二次确认）；正在使用的方案被删除时，切回自动方案。

## 5. 交互规格

### 5.1 明暗模式（下拉单行卡片）

- 切换判定基于**实际明暗**而非枚举值：跟随系统 → 浅色，且系统本是浅色 = 什么都没变——直接切换、**微调保留、不提醒**；只有实际明暗变化时，若有未保存微调才弹"放弃未保存的颜色？"确认（确认 = 切换 + 清微调）；
- 选中「我的方案」时整卡置灰并出现副标题解释（固定颜色不分明暗）。

### 5.2 取色弹窗（角色调色）

三段式布局：**头部固定**（角色名 + 说明 + 新颜色预览圆）→ **内容区单滚动**（色板全展开 + 自定义取色，无嵌套滚动源）→ **底部按钮固定**（重置 / 取消 / 应用）。

- 弹窗只有全开和关闭两种状态（无部分展开）；
- **色板按角色用途生成**（非静态大色表），见 §7.6；
- HSV 取色盘：色相条 + 饱和度/明度面板 + HEX 输入；点色板会让取色盘同步定位到该色；
- **重置是纯预览操作**：把取色状态拉回该角色的默认色（弹窗不关、数据库不动），预览色回到默认色时重置按钮自动置灰；
- **应用**（唯一提交按钮）：若选中的颜色恰好等于默认色，等价于撤销修改（清覆盖而非写入，避免出现假"已修改"标记）。

### 5.3 低对比待决胶囊

- 触发：应用了 ON 类角色且对比度 < 4.5:1 时（达标色静默生效，零打扰）；
- 形态：屏幕顶部悬浮胶囊，固定深底白字（不跟随主题——用户配色可能很糟，提醒必须可见），文案"对比度较低，可能看不清"+ [保留] [撤销]；
- 行为：悬浮于**所有页面之上**（含二级页），永不自动消失——用户可带着它浏览各页面的实际效果；保留 = 关闭胶囊颜色保留；撤销 = 只回滚触发它的那个角色；
- 新提醒替换旧提醒（继续调色 = 旧的隐含保留）；切换方案或恢复默认清空覆盖时，胶囊自动消失。

### 5.4 保存 / 重命名对话框

- 重名时输入框进入危险色，下方提示"已有同名方案，保存将会覆盖"；保存按钮保持可点（覆盖是有知情的选择）；
- 重命名撞名 = 覆盖：原同名方案删除，名字转移给被改名的方案。

### 5.5 长按气泡菜单

方案行长按（带 `LongPress` 触觉反馈）弹出锚定在该行的 `DropdownMenu`（非全局弹窗），菜单项：重命名、删除（危险色）。触觉规范见 CLAUDE.md 的「交互规范」章节。

## 6. 存储与兼容

- 全部存在 DataStore Preferences（非 Room）：方案名集合、临时覆盖表、明暗枚举、导入记录等；密钥类（`flowt.jks`、`local.properties` 的签名密码）不入库；
- 临时覆盖表与"我的方案"是**两层**：临时微调压在方案值之上；切换方案会清空临时微调（界面侧提前确认）；
- 旧格式迁移：早期"明暗编码进方案 id"（`violet@dark`）的记录在读取时自动拆分为方案 + 明暗两个字段；旧版保存方案（无派生态标记段）全部按覆盖值处理，行为与旧版一致。

## 7. 扩展指南

四类常见改动，各自只动有限的几处 —— 按"从最简单到最完整"排列。改任何一处之前，先读 §9 的坑。

### 7.1 修改部件所属的角色

- 自家部件：改 `FlowtColors.kt` 中对应颜色位字段右侧引用的角色，部件代码无需动；
- M3 显式传参类部件（底部导航栏、二级页顶栏）：去部件文件里改 `containerColor` 等参数引用的颜色位；
- 注意：颜色位的**消费端**（部件里 `FlowtColors.current.xxx`）不用动，改的只是"位 → 角色"的映射。

### 7.2 修改角色的默认颜色（预设方案）

预设的颜色值按**槽**写在 `PresetTheme.kt` 的 `lightColorScheme` / `darkColorScheme` 字面量里，角色到槽的映射见第 2 节表格。一个必须知道的覆盖规则：

> ⚠️ **深色方案的这些槽会被方案化处理覆盖**：`primaryContainer`（记账页底）、`tertiaryContainer`（指标卡底）、`surfaceContainerHighest`、`surfaceContainerLow`（卡片底）、`surfaceContainer`（导航栏底）、`secondaryContainer`（选中块）、`surface/background/surfaceDim`（页面底，统一纯黑）——手调它们无效，要改观感改 `mistFrom` / `tintedContainer` 的参数。浅色方案的记账页底与指标卡底同样是生成雾色（与手调值视觉收敛），字面量同样被覆盖。

### 7.3 新增一个角色

按顺序改五处（缺一处就是运行时或视觉 bug）：

1. `ColorRoles.kt` 的 `RoleKey` 枚举加一项：**ON 类必须声明在其 `pairsWith` 角色之后**（解析管线依赖声明顺序做单遍计算）；同时写 `withRoleValues`（决定写哪些色槽，**绝不与其他角色写同一槽**——两个角色写同一槽，后写的覆盖先写的）与默认值分支；
2. `FlowtColors.kt` 加颜色位字段（如果要有部件消费它）；
3. 部件改为读该颜色位；
4. 若要上方案预览：`AppearanceSettingsScreen.kt` 的 `previewRoles` 表加一项；
5. 若要专用色板候选：`ColorPalette.swatchesFor` 的 when 加分派。

### 7.4 新增一套预设方案

`PresetTheme.all` 列表加一项（字面量按第 2 节表格填基础槽即可）——方案化处理（容器雾化、色相注入、深色页面底纯黑）在构造时自动生效，无需手算。

### 7.5 调整容器注入强度 / 深色页面底颜色

全部在 `ColorRoles.kt` 的 `neutralizeLargeSurfaces`：`tintedContainer(...)` 的饱和度/明度参数控制卡片底与导航栏底的色调强度；深色页面底的三槽纯黑也在此处。改一处，预设与自动、浅色与深色（各自的分支）全部生效。

### 7.6 调整色板候选

`ColorPalette`：色相轴是 `hues` 列表（加一个度数 = 底色/强调/文字三类候选各多一列）；各角色的候选量级（饱和度/明度档位）在 `swatchesFor` 的生成参数里。语义色（危险/支出）是固定手工家族，不参与色相轮换。

### 7.7 调整派生算法 / 对比度阈值

`ColorMath.kt`：`CONTRAST_READABLE`（4.5，WCAG AA 正文底线，不建议下调）；`deriveOnColor` 的两段收敛参数。**修改后必须验证**：极端底色（纯黄、纯红、纯蓝、近黑、近白）派生结果对比度全部达标——这是"用户改底色不出错"的保证来源。

另外一条架构约束：**不引入取色、颜色科学、许可扫描类第三方库**——颜色计算（HSV、对比度、派生）全部手写于 `ColorMath.kt`，改动前先读其中的算法注释；这也是当初放弃 `material-color-utilities` 依赖的原因（其 Kotlin 移植的 stdlib 版本与项目编译器冲突，且手写方案零依赖、行为可控）。

### 7.8 调整低对比胶囊

状态与生命周期在 `AppViewModel`（全局单例状态 + 覆盖清空自动失效）；形态与文案在 `ui/LowContrastBanner.kt`（固定深底白字，不跟随主题——理由见其注释）；触发点在外观页的应用逻辑处。

## 8. 踩过的坑（必读）

这几条都是真实发生过的，不是假想。

### 坑 1：同一套观感规则实现了两份

方案化处理最初只接了深色：`PresetTheme` 构造时只对 `dark` 做雾化注入，**浅色字面量原样直通**；而"自动"方案又另写了一份手写容器雾化。结果：六套浅色的卡片底 / 导航栏底全是无个性的派生灰（六套看起来一样），自动方案的深色页面底也不是纯黑。

**教训**：观感规则**只实现一份**，所有路径（预设浅 / 深、自动浅 / 深）收敛到同一个函数。修复后 `neutralizeLargeSurfaces` 的浅色分支才真正开始工作。

### 坑 2：注入的槽与预览的角色错位

容器色相注入写的是 `secondaryContainer`（导航栏**选中块**的槽），预览表第六位却列着「导航栏**底色**」（`surfaceContainer` 槽）——注入生效了，预览位置却还是一个没被注入的槽，看起来"注入没生效"。

**教训**：注入哪个槽，预览就该展示那个槽对应的角色。两者必须同名同槽，且这类对应关系要有一张表（§2）可查。

### 坑 3：派生字色在高饱和底色上不达标

`deriveOnColor` 最初只拉明度：红 / 粉 / 蓝 这类色相的"最亮纯色"亮度本来就不够，明度拉到顶也只到 4.2:1，算法把不达标的颜色静默返回了——恰好触发了低对比胶囊。

**教训**：明度到边界仍不达标时必须**降饱和度**向纯白/纯黑收敛（派生必然达标）；对比度阈值不为派生结果让路——修算法，不修标准。

### 坑 4：M3 组件的默认色槽与角色体系不对齐

二级页顶栏（`TopAppBar`）默认读 `surface` 槽（「卡片底色」写入），底部导航默认读 `surfaceContainer`——都不在"导航栏"的语义里。表现：改导航栏相关角色，顶栏字色纹丝不动。

**教训**：M3 组件的默认色槽与自家角色体系**天然不对齐**，语义重要的组件必须显式传参（颜色位），并且由此诞生的每个新用途都要同步登记颜色位与角色（导航栏底色、导航栏文字两个角色就是这么来的）。
